# Offline-Admission Canonicalization and Golden Vectors

**Status:** local draft contract decision, 2026-11-09. Not published; no signer
or verifier is enabled.

## Fixed Strings

| Item | Value |
| --- | --- |
| Artifact `apiVersion` | `aegivela.io/offline-admission/v1.0` |
| Artifact `purpose` | `offline-admission` |
| Protected header `typ` | `aegivela-offline-admission+jws` |
| Algorithm | `EdDSA` (Ed25519) |
| Clock domain | `authority-utc` |

The protected header is exactly these members, serialized as JCS:
`{"alg":"EdDSA","kid":"<key id>","typ":"aegivela-offline-admission+jws"}`.
No other header members are accepted in v1.0. A missing, extra, reordered or
differently escaped header rejects. The key ID identifies a purpose-separated
offline-admission key; an ordinary execution-grant key is not reusable merely
because its `kid` appears in the same JWKS.

## Canonical Bytes

- Encoding is UTF-8. Objects are serialized by RFC 8785 JCS: members sorted by
  UTF-16 code units, no whitespace, `:` and `,` without spaces.
- Numbers use the ECMAScript `Number::toString` ordering required by RFC 8785
  for finite IEEE-754 doubles, including exponent thresholds (`1e-7`, `1e21`).
  `-0` serializes as `0`. Non-JSON numeric syntax, NaN, infinities, integer
  literals outside the interoperable safe range and invalid UTF-8 reject.
  Budget and epoch fields are additionally schema-capped at `9007199254740991`.
- The signing input is `base64url(headerCanonical) + "." + base64url(payloadCanonical)`.
- `parentGrantDigest` is lowercase SHA-256 hex over the exact verified parent
  compact JWS bytes, not a reserialized JSON view.
- `payloadDigest` is SHA-256 over JCS of
  `{"operationType": <exact allowlist value>, "payload": <request payload>}`.
- `bindingDigest` is SHA-256 over JCS of the signed authority/target binding:
  namespace, audience, action, resource reference, structured resource digest,
  task binding, scope, device reference/key/source epoch, parent grant
  reference/digest and validity.

## Golden Vectors

Generated by `scripts/offline-admission-vectors.mjs` from the valid artifact
fixture. The script uses Node's sorted-key serialization and ECMAScript number
formatting as an independent oracle for the documented subset.

| File | Purpose |
| --- | --- |
| `contracts/offline-admission/v1.0/vectors/protected-header.canonical.json` | Exact header bytes |
| `.../artifact-payload.canonical.json` | Exact artifact payload bytes |
| `.../binding.canonical.json` | Exact binding input bytes |
| `.../payload-input.canonical.json` | Exact payload digest input bytes |
| `.../number-format.json` | ES6 number-formatting vectors generated by the Node oracle |
| `.../signature.json` | Fixed Ed25519 verification vector: public key and signature only |
| `.../jwks.json` | Purpose-separated public JWKS entry |
| `.../manifest.json` | Base64url parts, signing input, SHA-256 digests and parent token |

Canonical files are exact bytes with no trailing newline. The Go contract test
recomputes them and fails on any drift. A fixed verification vector contains a
public key and signature only; no private test key is committed. The derivation
is publicly reproducible and explicitly non-production. Runtime rotation,
trust-bundle enforcement and compromise propagation remain implementation gates.

## Remaining Gate

Runtime key rotation, trust-bundle signature enforcement and publication remain
open. The design/owner review and G1 coordinates are accepted (see the
[signed-objects contract](offline-admission-signed-objects.md) and review
register); publication is still deferred. See
[Key Purpose and Lifecycle](offline-admission-key-lifecycle.md). Changing any fixed string above requires a new
contract review and regenerated vectors; it must not silently reuse existing
signed artifacts.
